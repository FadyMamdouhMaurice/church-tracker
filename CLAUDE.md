## Firebase Data Model

Collection: `records`

```js
// Student attendance
{ type:'attendance', studentId:Number, week:'YYYY-MM-DD', present:Boolean,
  date:'YYYY-MM-DD', by:String, classId:String, createdAt:ISO }

// Phone followup (افتقاد هاتفي) — always has note
{ type:'call', studentId:Number, date:'YYYY-MM-DD', note:String,
  by:String, classId:String, createdAt:ISO }

// Home visit (افتقاد بيتي)
{ type:'visit', studentId:Number, date:'YYYY-MM-DD', note:String,
  by:String, classId:String, createdAt:ISO }

// Servant attendance
{ type:'servant-attendance', servantName:String, week:'YYYY-MM-DD',
  present:Boolean, excused:Boolean, note:String,
  date:'YYYY-MM-DD', by:String, classId:String, createdAt:ISO }

// Student data edit (audit trail)
{ type:'student-edit', studentId:Number, date:'YYYY-MM-DD',
  note:String, by:String, classId:String, createdAt:ISO }
```

## Key Architectural Patterns

### State management (state.js)
```js
State.get('records')          // read
State.setRecords([...])       // write + persist + emit
State.addRecord(rec)          // optimistic add
State.updateStudent(updated)  // update student + persist
State.on('recordsChanged', fn) // subscribe
State.emit('customEvent', payload)
```

### Router (router.js)
```js
Router.go('home')              // navigate (pushes History entry)
Router.go('students', 'call')  // navigate with mode
Router.back()                  // go back
Router.getMode()               // current mode
Router.onEnter('home', fn)     // lifecycle hook
```
Screens: `login` | `loading` | `home` | `students` | `attendance` | `profile` | `admin` | `servant-att` | `edit`
Each screen div ID = `{screen}-screen`

### DB writes (db.js)
```js
await DB.write({ type:'attendance', studentId:1, ... })
// → optimistic State.addRecord()
// → Sheets.syncRecord() fire-and-forget
// → Firebase add (or offline queue if no connection)
```

### Offline queue
Pending writes stored in `localStorage['ct_queue']`.
Flushed automatically when back online.

### PWA updates (sw.js + updater.js)
To deploy an update that all users receive:
1. Make code changes
2. Bump `VERSION` in `sw.js`: `const VERSION = 'v3'`
3. Push to GitHub
4. Users see banner: "يوجد تحديث جديد — تحديث الآن"

## Common Tasks

### Add a new servant to a class
Edit `CONFIG.classes` in `js/config.js` — add name to `servants` array.

### Add a new class
1. Add tab in Google Sheet (name must match `CONFIG.classes[].name`)
2. Add entry to `CONFIG.classes` in `js/config.js`
3. No other changes needed — Apps Script reads all tabs dynamically

### Change admin password
Edit `CONFIG.admins.password` in `js/config.js`

### Change followup thresholds
Edit `CONFIG.followup` in `js/config.js`

### Deploy an update
```bash
# 1. Make changes
# 2. Bump VERSION in sw.js  (const VERSION = 'vX')
# 3. git add -A && git commit -m "..." && git push origin main
```

### Redeploy Apps Script (after Code.gs changes)
1. Open Apps Script editor
2. Deploy → **New deployment** (not Edit existing)
3. Web app → Execute as Me → Access: Anyone → Deploy
4. Update `CONFIG.sheets.scriptUrl` in `js/config.js` if URL changed

## Strict Rules (do not break these)

1. **No inline JS or CSS in index.html** — everything goes in separate files
2. **No hardcoded student data in JS** — all students come from Google Sheets
3. **All constants in config.js only** — never hardcode URLs, passwords, or IDs elsewhere
4. **Every DB write goes through `DB.write()`** — never call `firebase` directly from UI files
5. **Every screen navigation through `Router.go()`** — never manipulate `.active` class directly
6. **State changes through `State.*` methods** — never mutate `_data` directly
7. **After any Code.gs change → New Deployment required**
8. **Bump `sw.js VERSION` with every deploy** to ensure users get updates
